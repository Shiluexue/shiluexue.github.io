Narrative Scale

projects/ai-search.html — 六个层级，一套标记语法，四档字重

这一页不是通用排版规范，是 ai-search.html 专用的。原因很简单：dingtalk 和 homepage-design 是「一页一个项目，按阶段分段」，那里的 .l1 是 56px 浅灰 watermark，本来就该像背景刻度一样退后；而这一页是一条战略叙事里装了三个项目，Chapter 是叙事主干，不能退后，还多出一层。所以这里重建，不复用。

体系的核心判断是一句话：Prologue 和 Chapter 01/02/03 是同级的。它们都是这条叙事的「乐章」—— 引言讲为什么做，三个 Chapter 讲做了什么。读者的心智模型里它们是并列的，所以它们必须用完全相同的字号和字重，只靠 rail 里写的是 PROLOGUE 还是 CHAPTER 02 来区分。改之前引言是 38px/800 深色、Chapter 是 56px/400 浅灰，是两个互不相干的物种，读者判断不出谁高谁低。

去掉大写之后字距也要跟着收（.005em）—— 拉开字距的小写字看起来是坏的。同时透明度设了 0.6 下限：原来靠「大写+字距」撑可读性的标签，变小写之后必须靠颜色补回来。

Small type

小字的下限

改之前这一页有 32 个字号，17px 以下就有 17 个。现在小字只有三个。

问题不是某个字太小，是小字之间的差在 0.5–1px —— 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 15.5 / 16 全都在用。这种差人眼读不出层级，只读出「不整齐」。

17px 以下只允许三个

Size用在哪规则
15px次级正文 —— 卡片、面板、表格里的句子原来的 14 / 14.5 / 15 / 15.5 / 16 全部合并到这里
13px导航标签（T1 rail、T3 beat）+ 图注 / 脚注大写标签和小写图注共用一个字号，靠大小写和颜色区分
11px组件内的 micro label（Contains / Returns / 指标名）硬下限。任何要当句子读的文字都不许低于 13px

配套的两条：大写标签只有两种 —— 13px 蓝色带标记（导航）和 11px 灰色无标记（组件内部），不再有第三种；数字另算一档 —— 所有指标数字统一 --t-figure: 40px，原来的 32 / 34 / 38 / 44 合并。

唯一的例外：手机稿

页面里那些手机线框和社交卡片（.alt-* .soc-* .framework-viz .swipe-row .pain-circle）是把一个 UI 按 1:3 画出来的图，不是排版。它们的 7–9px 是画里的字，故意留在体系之外 —— 把它们拉到 11px 反而会让手机稿失真。页眉页脚同理。

Rhythm

间距体系

空白分两种：换气（break）和绑定（bind）。层级不是靠字号撑出来的，是靠空白。

参考 dingtalk 和 homepage-design：它们的 .l1 分段（Context / Problem / Design）上方留 160+32 = 192px，L2 模块留 64px，段落 16–24px。三档，比例约 3 倍。这一页的 T1 比它们的 .l1 高一级，T3 才是它们 .l1 的对位 —— 所以 T3 必须拿到接近 192px 的量级，T1 再往上走一档。

Break — 换气值宣告什么
--gap-movement240px换乐章（T1）。全页最大的空白，一页只出现 4 次
--gap-beat144px换步骤（T3，01 / 02 / 03）。原来是 76px —— 这就是「拥挤」的来源
--gap-sub64px换案例（T5）
--gap-block48px正文 ↔ 组件 / 图 / 面板
--gap-para24px段落 ↔ 段落
Bind — 绑定值把标题粘到它下面的内容
--bind-rail16pxrail → T1 标题
--bind-title12pxT1 标题 → T2 副标题
--bind-subject64pxT2 → 第一个 beat
--bind-beat16pxT3 → T4 claim
--bind-claim24pxT4 → 正文
--bind-sub12pxT5 → 正文

一条判据

break ≥ 4 × bind

标题上面的空白必须明显大于它下面的，否则读者会把标题读成上一段的结尾。T1：240 / 16 = 15 倍。T3：144 / 16 = 9 倍。T5：64 / 12 = 5 倍。越高的层级，这个比值越大 —— 这就是「呼吸感」的可计算定义。

实现方式：一条规则代替四十条

章节内部不再逐个组件写 margin。每个 beat 的直接子元素默认拿到 --gap-block 上下边距，相邻的会自动折叠成 48px 而不是叠成 96px；文字和标题再逐类覆盖回自己的 bind 值。

.op-beat > *          { margin: var(--gap-block) 0; }
.op-beat > .p         { margin-top:0; margin-bottom:var(--gap-para); }
.op-beat > .t-beat    { margin-top:0; margin-bottom:var(--bind-beat); }
.op-beat > .t-claim   { margin-top:0; margin-bottom:var(--bind-claim); }
.op-beat > .t-sub     { margin-top:var(--gap-sub); margin-bottom:var(--bind-sub); }
.op-beat > *:last-child { margin-bottom:0; }

Rules

怎么用

加 Chapter 03 的时候照这个套，不用再问。

Do

  • Chapter 03 用 <p class="t-rail">Chapter 03 · 项目名</p> + t-movement + t-subject，三行，和 Prologue / 02 一模一样。
  • T4 claim 写成完整的、可被反驳的句子。
  • T3 只写编号，不写标签文字；标签要说的东西写进 claim。
  • 断点只改 :root 变量。
  • 项目代号（EPIC）写进 rail，T2 只留定位描述句。
  • 新组件不写自己的 margin，交给 .op-beat > * 的 48px；要 T5 级别的分隔就加 .t-sub 或写进覆盖表。
  • 指标数字一律 var(--t-figure)。

Don’t

  • 不要在一个 Chapter 里出现第二个 T1 —— 那是在偷偷开新乐章，会把目录打乱。
  • 不要用 T4 claim 当章节标题：它没有 rail、没有编号，读者进不去导航。
  • 不要用 micro label（灰色小大写）当小节标题，它是组件内部的数据标签。
  • 不要回到 56px 浅灰 watermark。那是单项目页的阶段刻度，在这里会让 Chapter 比正文还轻。
  • 不要新增第五档字重。要更强的对比就调字号，不调字重。
  • 不要在 17px 以下新造字号。要更小就用 13，再小只有 11（且只在胶囊里），没有 12 和 14。
  • 不要给新标签加 text-transform:uppercase。全大写是 T1 rail 的专属形式。
  • 不要在一个 beat 里再放第二个浅灰数字。
  • 不要在断点里写 .t-movement{font-size:…}。只覆盖 :root 变量，否则间距不会跟着缩。
