CoReport

ChallengeGoogle Design Challenge
Duration7 days
Result✓ Passed
TagsMobile · Product Design · Research

UT Austin students rarely report facility issues outside dormitories, despite real problems existing across campus. CoReport is an online platform that allows students to report on-campus facility issues — connecting students, building managers, and maintenance staff into one efficient workflow.

The Opportunity

After interviewing UT Austin library managers, I discovered the campus lacked a dedicated maintenance reporting system that students could actually use. The existing tools were either staff-only or required too much manual effort to fill out accurately.

Research

Competitive Analysis

I examined three existing systems:

  • UT online maintenance request website — too much information required manually
  • WORQS — staff-only platform, inaccessible to students
  • Spiceworks — maintenance team tool with insufficient location specificity

User Research

5 contextual interviews with students (3 dorm-focused, 2 campus-focused) + 2 staff stakeholder interviews (IT coordinator, library building manager).

Key Pain Points

For Students

  • Having to travel to front desks just to report an issue
  • No feedback on maintenance timelines or outcomes
  • Difficulty finding the right reporting channel in unfamiliar buildings
  • Can't see if someone else already reported the same issue

For Maintenance Staff

  • Vague, incomplete problem descriptions
  • Inaccurate location information
  • False reports (e.g., computers that are just sleeping, not broken)
  • Redundant submissions for the same issue

Design Strategy

I reframed the solution around a three-stage verification workflow: students identify issues → building managers verify and add professional descriptions → maintenance receives accurate, actionable information.

Location Input

GPS/IPS indoor positioning combined with QR codes for precise device identification — solving the biggest pain point of inaccurate location data.

Problem Description

Pre-populated common issues tailored by location, reducing student effort while enabling manager verification before the ticket reaches maintenance.

Design Iterations

Iteration 1

Initial concept combining simplified reporting with reward systems — points and gamification for active reporters.

Iteration 2

Replaced extrinsic motivation (rewards) with intrinsic motivation — location-based common problem suggestions made reporting faster and more accurate without gamification overhead.

Iteration 3

Addressed the multiple-identical-devices problem by requiring QR code scanning — eliminates ambiguity when there are dozens of identical computers in a lab.

Final Design

Three primary workflows:

  1. Student reporting with automatic location detection
  2. Special case handling (wrong location, duplicates, multiple identical devices)
  3. Building manager verification and professional notation

Future Steps

  • Task-based usability testing with defined success metrics
  • MVP breakdown prioritizing user value versus implementation ease
  • Exploration of low-cost, non-digital alternatives for edge cases
  • Enhanced staff engagement integration for real-time status updates
